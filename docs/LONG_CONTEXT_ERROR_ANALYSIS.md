# Longer-input error analysis — v0.5

Historical raw files and captures remain unchanged. The two six-line demonstrations are exposed development evidence, not the new held-out stress test.

The original capture preserved all six original occurrences and their IDs. Its model supplied almost no temporal associations; one proposed during relationship required an after correction and was rejected because multiple earlier waits left its target unresolved. The explicit-ordinal capture also preserved every occurrence, but Gemma returned all `none`. These were complete valid model responses, not network/schema failures. The original prompt/schema made earlier IDs available; the adapter did not silently truncate source. The original and ordinal captures used 502/505 prompt tokens, generated 28/26 tokens, and stopped normally below their 184-token output budgets and 4096-token context windows. Raw fields remain in the original recording JSON. There is no evidence that generation hit a length limit.

Two mechanisms were therefore involved. First, the model was asked to discover all relationships while producing every source field in one constrained response. A complete-looking all-none object passed structural checks despite missed semantics. Second, the original verifier treated all earlier waits as a global ambiguity set; it had limited ordinal support and no heading scope. Repeated waits and deictic references could be rejected even when a section-local interpretation was plausible. The examples had no section boundary; repetition and antecedent ambiguity, rather than segmentation across headings, mattered there.

V4's unused context experiment still asked for a multi-field local object, and found only one of two desired links. V5 instead builds candidate records from exact original IDs, section paths, explicit IDs and ordinals. It asks Gemma for one relation to one selected source wait. It does not renumber or regenerate source text. Multiple plausible targets, absent antecedents and forward references become explicit unresolved states. Structural abstention uses no model call. A model `none` on a temporal candidate produces a visible review item without inventing a link.

Candidate selection and deterministic verification share scope rules. Source restrictions still govern timers independently of model output. User association corrections cannot enable a restricted wait. All candidates receive a coverage outcome; whole-line accounting remains source-preserving, not a claim that every sentence in an unstructured paragraph has been understood.

Development exposed one additional omission: plural `intervals`/`waits` did not match the first candidate-reference expression. This was fixed before the candidate freeze. The 20-case holdout and reference labels froze at `b1f1b4d`; the selected engine/evaluator froze at `3590ade`. No held-out retries or post-result prompt tuning. The final evaluation includes headings, repeated waits, ambiguity, monitoring, paragraphs, markup and adversarial text across 1–25 lines. Labels are assistant-authored and implementer-visible; independent review remains pending.

No targeted second pass was selected. The smallest design uses at most one focused classification per uniquely resolved temporal candidate, up to 12 calls and 180 seconds per run, with a 60 second per-call timeout. There is no measured claim that a second pass improves correction rate. Unresolved cases remain visible rather than triggering hidden retries.
