# Model evaluation — frozen candidate ac3038a

## Outcome

Actual local Gemma inference works. **Broad model usefulness is not established.**
The release candidate is a research preview, not a recommended laboratory workflow.
All 42 plans were source-valid; complete source coverage did not imply semantic accuracy.
The final pipeline offered 3 of 13 gold fixed waits, compared with 10 for guarded
rules. Both produced zero observed unsupported timer eligibility decisions.
The tiny accepted-timer sample is an important limitation of the zero-error result.

Timer eligibility is counterfactual availability, not a timer actually starting
automatically. Users click to start timers; no equipment is controlled. Model-only
eligibility uses the deterministic duration parser without the passive-source guard.
An exact time in a prohibited step is not a supported passive timer.

## What the model contributed, and what it did not

The model rejected the passive interpretation of all 10 false-positive passive lines
from starter rules, including prohibited incubation, a header, active/passive compound
work, monitoring, conditional timing and an injected instruction. One of these still
had the wrong non-passive category (`note` rather than `hands_on`). It also recognized
three paraphrases that rules missed, such as unattended instrument time. These are
semantic distinctions, not generated prose copied from a fixture.

That is evidence of narrower precision-oriented interpretation, **not overall model
superiority or demonstrated user benefit**. Gemma missed ordinary incubation,
undisturbed waiting and air-drying. Its F1 was slightly lower than starter rules.
The deterministic guard independently prevented every observed unsupported timer;
model necessity for that outcome was not established. It removed valid timer coverage
relative to guarded rules. The three recognized paraphrases all abstained at the
conservative final timer boundary.

The product claim is consequently narrowed to an **experimental source-linked review
assistant**, rather than a proven way to find more useful hands-off time. A future model
task should explicitly distinguish attention *during* an interval from the physical
act that begins it. That redesign must receive new development data and a separately
frozen prospective evaluation; this exposed holdout cannot be reused as unseen data.
No post-result prompt or policy changes have been made to this candidate.

## Data and independence

`evaluation/development.json`: 6 cases, 7 lines. `evaluation/holdout.json`: 42 cases,
45 lines. 26 held-out lines are semantically passive; 13 have gold fixed passive times.
Gold semantic labels and timer permission are distinct. Headers, prohibitions and
meta-instructions are notes; active/passive compound or interrupted instructions are
hands-on; vague or overnight passive waits remain semantically hands-off but have no
fixed timer. Cases include duplicate occurrences, numbered lines, negation, prompt
injection, repeated washes, negative/fractional/mixed time forms and paraphrases.

The coding assistant authored the synthetic labels before Gemma calls and froze them
in `4efb94f`. Labels were not generated by the evaluated model. The implementer could
see them; there was no blinded external annotator, independent human adjudication or
real-world laboratory validation. Familiar patterns recur across splits. Interpret
this as a small prospective synthetic test, not a population accuracy estimate.

Schema and model selection used development only. Candidate `ac3038a` and
`evaluation/candidate-freeze.json` froze the app/evaluator before one held-out pass.
The evaluator verifies SHA-256 and refuses to overwrite run artifacts. No held-out
retries, denominator changes or tuning followed. The source validator's adversarial
unit tests are separate software tests, not additional model benchmark examples.

## Reproduce and audit

Use the commands in README. Run with the pinned Python environment if possible.
The candidate hashes must match. A changed prompt/policy needs a new candidate and
new test data. A repeated run of this now-exposed holdout is a replication, not unseen.
Original starter is in `9f56212`; all code and data freezes are separate local commits.
Public repository publication is pending approval.

Unit/API tests and the 32/32 deterministic duration checks prove only their explicit
software assertions. Chromium screenshots and 19 interaction checks cover the UI.
The live video is a separate selected example, not the benchmark denominator.
Its first attempted incubation example returned no eligible timer and is preserved
as `live-ui-first-attempt.json`; a subsequent wait example must be labeled as selected.
No sensitive protocols or closed model substitution were used. Internet-disconnected
operation and actual human time savings have not been tested.
